変更した画面が Figma のデザインどおりに表示されているかを突合してください。引数: $ARGUMENTS(Figma のフレーム URL、実装画面の URL、幅、比較元ブランチ。すべて省略可)

あなたの役割は「デザインと違う画面が PR に出るのを防ぐ」ことです。コードの品質(review-loop)やテストの有無(test-plan)は見ない。**修正はしない**(指摘を出すところまで。直すのはユーザーの指示か /atdd の中で)。

## 手順

### 1. 対象を決める

1. スクリプトの場所: `${CLAUDE_PLUGIN_ROOT}/scripts/`。無ければ `find ~/.claude/plugins -path '*design-check*' -name design-refs.sh 2>/dev/null | head -1` の dirname
2. `<scripts-dir>/review-diff.sh --stat <比較元>` で比較元(先頭行 `# base: ...`)と変更ファイル一覧を取り、**最初にユーザーへ提示する**。差分ゼロなら終了
3. **Figma の参照**を次の順で集める: 引数の figma.com URL → `<scripts-dir>/design-refs.sh`(テスト計画 `.claude/specs/<branch>.md` の「## デザイン(Figma)」節 → PR 本文) → 会話中・Notion タスク・チケットの figma.com リンク。**1 つも無ければ、ユーザーに Figma の URL を 1 問で聞いて止まる**(推測で似た画面を探さない)
4. **実装画面**を次の順で決める: 引数の URL → デザイン節の `→` 右側 → 差分のルート定義・ページファイルから URL パスを割り出し、開発サーバ(`http://localhost:<port>`。port は package.json / CLAUDE.md / .env から)で開く。画面ごとに「Figma フレーム ↔ 実装 URL(またはコンポーネントファイル)」の対応表を作ってから次へ
5. 引数や Figma 参照に無いものは、ユーザーに 1 問だけ聞いてよい(開発サーバの URL・ログイン方法)。それ以外は「確認できなかったもの」として報告に残す

### 2. Figma 側の「要素リスト」を作る

Figma MCP(名前は環境で違う。`get_design_context` / `get_metadata` / `get_screenshot` / `get_variable_defs` を持つもの)で、フレームごとに:

- `get_metadata`: ノードツリー(名前・種類・位置・サイズ)。**画面に見える要素の一覧と順序**をここから起こす
- `get_design_context`: 文言・フォント・色・余白・トークン名。テキストは **原文どおり**(句読点・全角半角・単位・空状態の文言まで)
- `get_screenshot`: 見た目の比較用
- 必要なら `get_variable_defs`: トークン → 実値

Figma MCP が使えないときは止まって「Figma MCP が接続されていない」と報告する(スクリーンショットの貼り付けをユーザーに頼んでもよい。その場合は文言と要素の有無だけ突合し、レベルを L0 と記す)。

要素リストの粒度: テキスト・ボタン・リンク・入力欄・画像/アイコン・バッジ・区切り・カード。装飾用の矩形やオートレイアウトの入れ物は要素にしない(その余白・背景は親要素の属性として見る)。

### 3. 実装側の「要素リスト」を作る(できる最も高いレベルで)

| レベル | 何を見るか | 必要なもの |
|---|---|---|
| **L3 見た目** | 同じ幅で撮った実装のスクリーンショットと Figma のスクリーンショットを見比べる | ブラウザ MCP + 動く画面 |
| **L2 DOM** | `<scripts-dir>/dom-snapshot.js` を画面上で実行し、要素・文言・順序・計算済みスタイルを取る | ブラウザ MCP + 動く画面 |
| **L1 静的** | 差分のコンポーネント / テンプレート / CSS を読み、要素・文言・トークンを起こす | ソースのみ |

ブラウザ MCP(Claude in Chrome: `tabs_create_mcp` → `navigate` → `resize_window` → `javascript_tool` / `computer` のスクリーンショット。Playwright: `browser_navigate` → `browser_resize` → `browser_evaluate` → `browser_take_screenshot`)が使え、実装 URL が開けるなら **L2 と L3 の両方**を行う。手順:

1. 幅を Figma フレームの幅に合わせる(引数 `<幅>px` があればそれ。デスクトップ 1280 / モバイル 375 が目安)
2. `dom-snapshot.js` の中身を Read して、そのままページで実行する(Playwright の `browser_evaluate` は `() => { ... }` の関数形にする)。返った JSON の `elements` が実装側の要素リスト
3. 同じ状態でスクリーンショットを撮る
4. Figma に **状態のバリエーション**(hover / disabled / error / empty / loading)やモバイルフレームがあれば、その状態を作れる範囲で作って(データが要るものは「確認できなかった」に)同じことを繰り返す

ブラウザが使えない・画面が開けない(ログインが要る・データが無い)ときは L1 で行い、報告にレベルと理由を明記する。**L1 でも文言と要素の有無は必ず突合する。**

### 4. 突合する

Figma の要素リストを基準に、1 要素ずつ実装側と対応づけて次を見る:

| 観点 | 見るもの | 深刻度 |
|---|---|---|
| 要素の有無・順序 | Figma にある要素が実装に無い / 順序が違う / Figma に無い要素が実装にある | 🔴 Critical(増えている要素は意図の確認として 🟡) |
| 文言 | 見出し・ラベル・ボタン・プレースホルダ・空状態・エラー文言が原文どおりか(句読点・全角半角・単位・改行位置) | 🔴 Critical |
| 操作要素 | ボタン・リンク・入力欄が正しい種類か(リンクがボタンになっている等)、disabled の有無 | 🔴 Critical |
| 状態 | Figma にある状態(hover / disabled / error / empty / loading)が実装にあるか | 🟡 Warning |
| 色 | 文字色・背景・ボーダーがトークン(または実値)で一致するか | 🟡 Warning |
| タイポ | フォントサイズ・ウェイト・行間 | 🟡 Warning(2px 以内の行間差は 🔵) |
| 余白・サイズ | 要素の高さ・パディング・要素間の gap・角丸 | 🟡 Warning(3px 以上)/ 🔵 Info(2px 以内) |
| レスポンシブ | Figma に複数幅のフレームがあれば各幅で上記 | 幅ごとに同じ基準 |
| アクセシビリティ | 画像の alt・アイコンボタンの aria-label・見出しレベル | 🔵 Info |

- 突合はトークン名を優先する(Figma の `color/text/primary` と実装の CSS 変数・Tailwind クラスが同じトークンを指していれば実値の丸めは問わない)
- スクリーンショット同士の比較は「DOM で見つけた差分の裏取り」と「DOM に出ないもの(画像の中身・アイコン・影・グラデーション)」に使う。印象だけで指摘しない(必ず要素と値を添える)
- 差分に含まれない画面・要素は見ない(ただし差分が共通コンポーネントを変えていれば、その影響先は「確認できなかったもの」に列挙する)

### 5. 報告する

```
# デザイン突合結果(比較元: <base> / 画面 N 件 / レベル: L3+L2 | L2 | L1 | L0)

## 画面: <名前>(Figma: <URL> / 実装: <URL または ファイル> / 幅: 1280px)
| # | Figma の要素 | 実装 | 一致 | 差分 |
|---|---|---|---|---|
| 1 | 見出し「注文一覧」 24/32 Bold text/primary | h1「注文一覧」 24/32 700 #1A1A1A | ✅ | |
| 2 | ボタン「CSV エクスポート」 primary | (無し) | ❌ | 要素欠落 |
| 3 | 空状態「注文はまだありません。」 | 「注文がありません」 | ❌ | 文言違い(句点・「まだ」) |

## 🔴 Critical(欠落・文言違い・操作要素の不足)
- [画面] 要素 — 何が違うか / 修正案(ファイル:行)

## 🟡 Warning(状態・色・タイポ・余白のずれ)
## 🔵 Info(微差・アクセシビリティ)
## 🔍 確認できなかったもの(状態・幅・ブラウザ無し・データ無し など理由つき)
## ✅ 一致していた主要ポイント(3〜5 行)

## 判定: 合格 / 不合格
```

6. ログ: `<scripts-dir>/events-log.sh design_check.result screens=<画面数> level=<0|1|2|3> critical=<n> warning=<n> info=<n> verdict=<pass|fail>`(verdict は Critical + Warning が 0 なら pass)
7. **合格**なら `<scripts-dir>/mark-design-passed.sh <比較元>` でマーカーを書く。不合格ならマーカーは書かず、直すべき点を列挙して終了する。スクリーンショットを撮った場合は `.claude/design/<branch>/<画面名>-<幅>.png` に残し、パスを報告に添える(ディレクトリは作る。コミットはしない)

## ルール

- Figma の URL を推測で選ばない。無ければ聞く
- 文言は「意味が同じ」ではなく **文字列として同じ** かで判定する(表記ゆれは Critical。意図的な変更ならユーザーがそう言う)
- 見た目の印象で合否を決めない。指摘には必ず「Figma の値 / 実装の値 / 場所」を付ける
- 確認できなかったものを「たぶん合っている」で合格にしない。列挙して判定は残りで行い、レベルを正直に書く
- 修正はしない。修正後に再実行すると差分ハッシュが変わるのでマーカーも取り直しになる
