これから実装するタスクの受け入れ基準を作成してください。引数: $ARGUMENTS(タスクの説明。省略時は会話の文脈から把握する)

## 手順

1. タスクの内容を把握する($ARGUMENTS、会話の文脈、参照されたチケット・仕様ドキュメント)
2. 不明点が実装の成否に関わる場合は、受け入れ基準を書く前にユーザーに質問する(最大3問まで。細部は「要確認」として基準に残してよい)
3. 現在のブランチ名を取得し、`.claude/specs/<ブランチ名のスラッシュを-に置換>.md` に以下の形式で受け入れ基準を書く:

```markdown
# 受け入れ基準: <タスク名>
作成: <日付> / ブランチ: <ブランチ名>

## 目的(1〜2行)

## 受け入れ基準
- [ ] AC-1: <観測可能な振る舞い。「〜したとき〜になる」形式>
- [ ] AC-2: ...

## エッジケース
- [ ] EC-1: <空・0件・境界値・同時実行・失敗時など>

## 変更してはいけないこと(非目標・既存動作の維持)
- NG-1: ...

## 要確認(仕様が曖昧な点)
- Q-1: ...
```

4. 書いた受け入れ基準をユーザーに提示し、**承認を得てから**実装に着手する

## ルール

- 受け入れ基準は「コードがどう書かれるか」ではなく「外から観測できる振る舞い」で書く
- 1タスクの基準は5〜10個程度。それを超えるならタスク分割を提案する
- このファイルは spec-compliance-reviewer がレビュー時の仕様ソースとして最優先で参照する。実装中に仕様が変わったら、コードではなく**先にこのファイルを更新**すること
